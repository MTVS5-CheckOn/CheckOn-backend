# 융합 프로젝트 중간 결과 보고서

**팀명 : CHECKON  |  프로젝트명 : CHECKON**

**체크온(Check-On) — 수능 대비 고등 국어 학원 강사를 위한 AI 운영 보조 도구**
**개발 기간 : 2026. 7. 13 ~ 8. 27 (약 6.5주)**
**팀 구성 : AI 박진희·염준영 / BE 한승우 / FR 라정우**

> **한 줄 정의** — 학원 강사가 담당 학생 30명을 일일이 챙길 시간이 없어 '무너지는 학생'을 뒤늦게 아는 문제를, 학습 기록의 신호 감지 → 개입 우선순위 → 소통·처방 초안으로 잇는 교사용 분석 레이어.
> **설계 원칙** — AI는 판단을 대신하지 않는다. 최종 판단과 발송은 언제나 강사가 한다.

## 1-① 프로젝트 소개

체크온은 학생용 학습 앱이 아니라 **교사용 운영 레이어**다. 시장의 AI 학습 서비스가 학생에게 문제를 풀리는 데 집중하는 반면, 체크온은 강사의 운영 의사결정("오늘 누구를 먼저 챙길까")을 돕는다.

### 핵심 기능 3축

- **① 학생 위험신호 감지** — 학습 기록에서 평소와 달라진 신호를 찾아 "오늘 확인할 학생 TOP N"을 제시한다.
- **② 학부모 상담 초안** — 학부모별 라벨을 근거로 그 학부모에게 맞는 상담·답변 초안을 미리 만들어 둔다.
- **③ 학생 개인 맞춤 문제** — 약한 영역·유형을 짚어 보강 문항을 생성하고, 강사 승인 후 학생이 푼다.

**범위와 타깃** — v1은 수능 대비 고등 국어(독서·문학·화법과작문·언어와매체) 객관식부터 시작한다. 타깃은 학원(원장)이 아니라 **강사 개인**이며, 원장이 도입·예산을 승인할 수 있다.

## 1-② 개발배경 및 목적

### 층위 1 · 시장 — 생존 과제가 모집에서 유지로 바뀌었다

초중고 학생 수는 2024년 513만 명에서 2025년 502만 명으로 감소했다. 동시에 **고등학교 사교육 참여율 63.0%(전년 대비 −4.3%p), 참여 학생 월평균 79.3만 원**으로 학교급 중 가장 높다.

> **고등학교는 참여 학생의 월평균 지출이 가장 높은 학교급이며, 체크온은 이 운영 구간을 1차 타깃으로 삼는다.**

그런데 **학원 단위 이탈률은 공개 데이터가 존재하지 않는다.** 국가 통계도 조사 항목에 없어, 강사는 지금 자기 감으로만 알고 있다. 이 공백이 곧 체크온이 채우려는 자리다.

### 층위 2 · 교사 운영 — 판단이 아닌 일에 묶여 있다

강사 1인이 30~100명을 담당하는데, 교사 업무의 20~30%가 채점·준비·행정이다. 교사 조사에서 **76.1%가 번아웃을 경험**했고 학부모 상담이 잦을수록 소진이 비례해 늘었다. 약점이 다 다른 걸 알면서도 출제 시간이 없어 30명에게 같은 숙제를 낸다.

### 층위 3 · 기술 — 숨은 위기 학생은 단순 규칙으로 못 잡는다

가장 위험한 학생은 성적이 떨어진 학생이 아니라 겉으로 멀쩡한 학생이다. 정답률은 유지되는데 풀이시간만 2배로 늘어난 경우가 그 예로, 학습분석에서 **wheel-spinning**이라 부르는 실재 현상이다. 이탈도 갑자기 오지 않는다 — 추적 연구에서 이탈 학생은 전체 일수의 **57%만 출석**한 반면 남은 학생은 87%를 출석했다. 참여 행동이 먼저 갈라진다.

합성 로그 기반 자체 시뮬레이션에서도 절대 임계값 규칙은 숨은 위기의 **34%**만 탐지한 반면, 개인 베이스라인 대비 상대 변화로 보면 **63%**까지 올랐다. 감지 규칙 6종을 전부 상대 변화 기반으로 설계한 이유다.

> **핵심 문제 진술** — 학원 강사는 유지가 절박해진 시장에서, 무너지는 학생을 뒤늦게 알아채고, 정작 위험한 숨은 위기 학생은 단순 규칙으로 걸러지지 않아, 누구를 먼저 챙겨야 할지 판단할 근거를 얻지 못한다.

## 1-③ 기대효과 및 활용분야

- **강사(주요 사용자)** — 하루 10~15분으로 담당 학생 전원을 점검한다. 학생 유지 효과와 구독료의 관계는 파일럿에서 검증한다.
- **학부모·학생** — 학부모는 아이에 맞춘 소통을 받아 뒤늦은 폭발이 이른 상의로 바뀐다. 학생은 약점에 맞는 문제를 받는다(신호·랭킹은 낙인 방지를 위해 미노출).
- **정량 목표(3년)** — 유료 구독 강사 1,000~1,500명, 경보→개입 전환율 50% 이상, 재등록률 개선 코호트 실증 1건 이상.

### 활용분야

**1차는 사교육**이다. 2025년 고등학교 전체 사교육비는 7.8조 원이며, 고등 국어 세부 시장 규모와 도구 대안은 추가 검증이 필요하다. **2차는 타 과목 확장** — 감지·소통 엔진이 과목 중립적이다. **3차는 공교육 조기경보(EWS) 보완**으로, 국내 초중등 적용 가능성은 별도 검토한다.

## 1-④ 팀구성 및 역할

- **AI · 박진희** — 위험신호 감지 엔진, 브리핑 문장화와 왜곡 게이트, 실명 마스킹, 스마트 엑셀 Import
- **AI · 염준영** — 약점 진단, 문항 생성 파이프라인, 검증 게이트(교차 풀이), LLM 게이트웨이
- **BE · 한승우** — Java/Spring 도메인 원장(MySQL), 동의·별칭 관리, 새벽 배치, AI 서비스 연동
- **FR · 라정우** — 오늘의 브리핑, 출제 스튜디오, 학부모 웹뷰, 온보딩 화면

**운영 원칙** — 자체 모델을 만들지 않고 OpenAI 호환 LLM(로컬 포함) + 검증 게이트로 구현해 리소스를 감지·검증 품질에 집중시킨다. LLM 접점은 벤더 독립 구조로 두어 어느 쪽으로도 전환할 수 있다.

## 2-① 개발환경 및 개발언어

- **AI 서비스** — Python 3.12(uv) · FastAPI + Uvicorn · LangGraph 1.x 상태기계 · PostgreSQL 16 / SQLAlchemy 2.0 async · Alembic · langgraph-checkpoint-postgres(재시작 생존) · OpenAI SDK 어댑터 + 공용 게이트웨이 · pandas/numpy/openpyxl
- **백엔드·프론트엔드** — 백엔드는 Java/Spring + MySQL로 도메인 원장과 새벽 배치를 담당한다. 프론트엔드는 PC 웹을 작업용, 모바일을 확인용으로 나누며 실제 이용 맥락은 파일럿에서 검증한다.
- **품질 관리** — ruff 정적 분석 · mypy strict · pytest(실 LLM·실 DB는 integration 마커로 분리) · Docker Compose. CI는 GitHub Actions **2중 게이트**(코드 품질 / 실 DB 통합)로 매 커밋 검증한다.

## 2-② 시스템 구성 및 아키텍처

![체크온 시스템 아키텍처](아키텍쳐%20융프-1차발표용.png)

*▲ 프론트엔드 · 백엔드 · AI 서비스 전체 흐름 — 실명 구역과 개인정보 무접촉 구역의 경계*

데이터 레이어는 풀이 로그·출결·상담 기록·학부모 라벨을 트랙 A(타사 엑셀)·B(자체 기록)·C(외부 연동)로 수집해 표준화한다. 분석·개입 레이어는 **진단**(규칙 6종 → 우선순위 TOP N) → **처방**(약점 진단 → 문항 생성 → 3중 검증 → 강사 승인) → **보고** → **소통** 네 단계로 돌고, 학생의 풀이 결과가 다시 진단의 재료가 되어 루프가 닫힌다.

### 아키텍처 원칙 — 원칙을 문서가 아니라 구조로 강제한다

- **판정은 결정론, LLM은 표현만.** 위험신호 판정에 LLM이 관여하지 않는다. 문장화가 실패해도 판정은 변하지 않는다.
- **개인정보 무접촉 5단.** 동의 → 가명 처리(AI DB에 실명 컬럼 자체가 없음) → LLM 무접촉 → 출처 게이트 → 강사 승인. 개발 테스트셋의 마스킹 미탐 0건을 CI가 검사하며 운영 성능은 별도 검증한다.
- **모든 출력은 초안이다.** 발송 버튼이 체크온에 없다. 최종 판단과 발송은 강사의 채널에서 이뤄진다.
- **전 AI 실행의 감사 원장.** 왜 이 결과인가를 역추적한다. AI 관련 법령의 인간 감독·설명 가능성 취지에 대응한다.
- **신뢰성 공학.** 멱등·영속·중복 실행 차단·부분 실패 시 산출물 보존을 계약과 테스트로 고정했다.

## 2-③ 주요 기능

### 필수 기능(Must) — 감지 → 개입 → 기록 한 바퀴의 최소 단위

- **F1 데이터 수집** — 타사 엑셀·강사 입력·학생 홈 제출을 표준화하고 마스킹해 통합 학습 기록을 만든다.
- **F2 이상신호 감지** — 판정 창 2주, 직전 8주 기준선으로 규칙 6종(정답률 하락·제출 저조·학습 공백·숨은 위기·복귀 케어·유형 편중). 전부 상대 변화 기반이며 근거 기록이 필수 첨부된다.
- **F3 오늘의 브리핑** — TOP 3~5 상한, 같은 신호 2주 쿨다운 후 문장화해 강사 브리핑에 표시한다. 왜곡 게이트 통과분만 제공한다.
- **F4·F5 경보 근거 보기·피드백** — 어떤 원본 기록 때문에 떴는지 역추적해 보여주고, 해당 없음 평가를 임계값 보정 재료로 축적한다.
- **F6·F7 학부모 라벨과 상담 초안** — 4축(성향·관심사·민감도·빈도)으로 30초 태깅하고, 기록·신호·이력·라벨을 근거 패키지로 묶어 초안을 만든다. 출처 게이트가 근거 없는 문장을 막는다.
- **F8 약점 기반 보강 출제** — 3중 검증(규칙 검증 → 별도 모델 교차 풀이 → 강사 승인). 강사 승인은 생략할 수 없다.
- **F9·F10 동의 관리와 월간 리포트** — 동의가 없으면 그 학생은 AI 분석 대상에서 제외된다. 리포트는 라벨별 버전으로 생성한다.

### 하지 않는 것(Won't) — 스코프를 지키는 명시적 배제

**이탈 확률 예측**은 퇴원 라벨이 쌓인 뒤로 미루고 주의가 필요한 학생 랭킹까지만 구현한다. 원장 대시보드·수납은 학원 플랜으로 이월한다. 학생·학부모 화면에 신호를 노출하지 않고(낙인 방지), AI가 학생에게 직접 해설을 주지 않으며(튜터화 금지), 자체 발송 기능도 두지 않는다.

## 2-④ 생성형 AI 활용 내용

제품에 내장된 생성형 AI와 개발 과정에서의 활용, 두 층위 모두에 같은 원칙을 적용했다 — **생성 결과를 그대로 쓰지 않고 반드시 검증 게이트와 사람의 확정을 거친다.**

### (1) 제품에 내장된 생성형 AI

- **신호 브리핑 문장화** — 결정론 규칙의 판정과 근거를 읽을 문장으로 변환한다. 왜곡 게이트 통과분만 발신되고, 실패 시 결정론 템플릿으로 폴백한다.
- **학부모 상담·답변 초안** — 기록·신호·라벨·이력을 근거로 그 학부모의 톤에 맞춰 생성하고, 출처 게이트가 근거 없는 수치를 차단한다.
- **개인 맞춤 문항 생성** — 국어는 지문이 곧 콘텐츠라 기출을 그대로 쓰면 저작권 리스크가 있다. 비문학은 취약 주제에 맞춰 지문을 생성하고 문학은 저작권 만료 작품으로 구성한다. **학생마다 다른 지문은 기존 문제은행과 다른 생성·검증 절차가 필요하다.**
- **활용하지 않는 곳** — 위험신호 판정. 판정은 결정론 규칙이 소유하며, LLM이 실패해도 판정은 변하지 않는다.

> **왜곡 게이트 — 가정이 아니라 기록이다.** 개발 중 LLM이 근거 수치(50 / 75)를 임의로 "약 2/3 수준"으로 환산한 사례가 있었다. 게이트가 그 문장을 차단했고 브리핑은 결정론 템플릿으로 폴백됐다. 측정치는 문장화 평균 0.6초, 신호 7건 브리핑 2.3초, 마스킹 미탐 0건이며 모두 개발 테스트 기준이다.

### (2) 개발 과정에서의 활용

- **기획·근거 조사** — 문제를 세 층위로 구조화하고 각각 다른 근거로 받쳤다. 프리모템으로 실패 시나리오를 역산했고, 통계 대조 중 인용 수치가 한 해 전 기준임을 발견해 교체했다. **학원 이탈률 데이터의 부재를 확인하고 그 부재 자체를 문제 정의의 근거로 전환**했다.
- **규제 → 아키텍처 번역** — AI 기본법의 인간 감독·설명 가능성·감사 로그 요구를 판정은 결정론 / LLM은 표현만 / 전 실행 원장 기록 / HITL 필수라는 구체적 제약으로 옮겼다.
- **구현·검증** — 코드 작성에 AI를 쓰되 ruff·mypy·자동 테스트·2중 CI를 통과해야만 병합되도록 했다. 설계 원칙을 문서가 아니라 **테스트와 계약으로 고정**해 회귀를 막았다.

## 2-⑤ 기타 — 인용 근거 및 한계

### 주요 출처

## 3. 진행 일정 및 개발 진척도

### 완료 — 문제출제(M2) 이전 기반 구간

- **기획·설계·환경** — 문제 정의 3층위, 아키텍처 설계(판정/표현 분리, 게이트, 무접촉 5단, 모듈 경계), 개발 환경과 CI 2중 게이트 구축.
- **데이터 수집·스마트 Import** — 타사 엑셀 컬럼 의미를 AI로 추론해 매핑을 제안한다. 시그니처 캐시로 같은 양식 재수입 시 AI 호출 0회, 실패 시 수동 매핑 폴백.
- **위험신호 감지 엔진** — 규칙 6종을 전부 상대 변화 기준으로 구현. 세그먼트 처리, TOP 3~5 상한, 쿨다운 2주, 리마인드 lifecycle 포함. 감지 시나리오 골든셋으로 회귀를 고정했다.
- **약점 진단** — 영역·유형 체계에서 어느 단이 막혔는지 판별하는 모듈과 진단 골든셋 확보.
- **브리핑 문장화·왜곡 게이트·마스킹** — 근거 패키지 → 실 LLM 문장화 → 게이트 → 폴백 파이프라인 완성. 게이트가 환산 수치를 실제로 차단한 사례 확보. 실명 토큰화와 CI 미탐 0 검사 구축.
- **에이전트 기반·계약·영속 계층** — 상태기계, 멱등·영속, 중복 실행 차단, 감사 원장. contracts 계층, SQLAlchemy·Alembic, FastAPI 엔드포인트, 평가 기반까지 구축.

### 진행 중 — 문제출제(M2)

문항 생성 워크플로, 3중 게이트, 난이도 밴드, 검증 통과본 불변 스냅숏, 프롬프트 템플릿과 골든 코퍼스를 구현 중이다. 평가원 문제 형식과의 적합성 검토를 병행해 자료 블록·배점·공유 문항군 계약을 정리하고 있다. PR 리뷰·A+B 승인·실모델 API 키 연결은 대기 중이다.

### 예정

- **소통 — 상담팩·리포트** — 라벨 4축 태깅과 톤 조절을 구현하고, 완성된 문장화·게이트 기반 위에 상담 초안 본체와 월간 리포트를 조립할 예정이다.
- **화면 통합·연동** — 프론트 주요 화면을 구현하고 Spring 도메인 원장과 연동해 수집 → 감지 → 브리핑 → 개입 → 기록 루프를 End-to-End로 검증할 예정이다.
- **안정화·제출** — 통합 테스트와 성능 점검을 거쳐 데모 시나리오(김 선생의 하루)를 구성한다.

### 완료 판정 기준 · 리스크

**판정 기준** — ① 핵심 3축이 최소 형태로 End-to-End 동작 ② 설계 원칙이 코드로 강제(판정에 LLM 미관여, 근거 필수, 마스킹 미탐 0, 강사 승인 생략 불가) ③ 자동 테스트와 2중 CI 통과 ④ 하루 10~15분 안에 한 바퀴가 도는 것을 데모로 증명.

**리스크** — ① **입력 중단**(가장 개연성 높은 실패)은 시간 예산을 설계 제약으로 강제하고 라이트 모드를 둔다. ② **오경보로 인한 신뢰 붕괴**는 정밀도를 재현율보다 우선하고 해당 없음이 30%를 넘으면 임계값을 보수화한다. ③ **원장의 사용 차단**은 강사·원장 요구를 분리 검증하고 무접촉 구조를 근거로 제시한다.
